Cache purge checklist

Use this before approving a CDN/cache purge request. Keep CDN tokens, API keys, cookies, sessions, signed URLs, customer URLs, origin hostnames, internal URLs, raw logs, credentials, PII, and production data out of public tools.

1. State purge scope and method

  • CDN/platform, zone/service/property, environment, hostname, URL, path prefix, tag, surrogate key, CP code, or cache key
  • Purge method: invalidate, delete, soft purge, ban, purge by URL, tag, prefix, host, key, CP code, or emergency broad purge
  • Exact page types affected: HTML, assets, API-adjacent paths, logged-in pages, cart, checkout, account, pricing, product, CMS, or tenant pages

2. Check cache-key and origin risk

  • Query strings, headers, cookies, device, locale, tenant, auth state, and Vary behavior
  • Origin load, origin shield, stale-while-revalidate, stale-if-error, TTL, revalidation, warm-up, and rate-limit risk
  • Whether delete-style purges can force origin retrieval or create a miss storm

3. Define cause, validation, and ownership

  • Cause and urgency: deploy, CMS publish, pricing/product inventory update, security incident, wrong content, image/CSS/JS release, or legal takedown
  • Validation: sample URLs, cache-status/header checks, HIT/MISS, Age, x-cache or cf-cache-status, edge location, before/after evidence, and monitoring
  • Named owner, reviewer, approver, escalation path, comms owner, and next update time

4. Avoid unsafe wording and private data

  • Avoid "purge everything", "delete all", "clear cache", "no origin risk", "no customer impact", "ignore query strings", or "force refresh" unless separately reviewed and approved.
  • Do not paste API tokens, bearer tokens, cookies, sessions, signed URLs, customer URLs, origin hostnames, internal URLs, raw logs, credentials, PII, or production data.
  • Document blast radius and origin-load risk honestly, even when the purge is urgent.
